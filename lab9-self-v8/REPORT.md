# Звіт до самостійної роботи No10

## Навіщо делегати

`Func<T, TResult>` передає у `Map` перетворення елементів, `Predicate<T>` — правило перевірки для `Filter`, а `Action<T>` — процедуру для `ForEach`. Делегат дозволяє використовувати однакову реалізацію обходу з різною поведінкою: утиліта не прив’язана до конкретного поля чи класу.

## Як лямбда-вирази спрощують виклик

Лямбда-вирази стисло описують поведінку напряму в виклику:

```csharp
CollectionUtils.MaxBy(products, p => p.Price);
CollectionUtils.Filter(products, p => p.Price > 1_000);
CollectionUtils.ForEach(numbers, n => Console.WriteLine(n));
```

Компілятор сам знаходить типи параметрів і приводить лямбду до `Func`/`Predicate`/`Action`.

## Порівняння з LINQ

- `Map` відповідає `Enumerable.Select`;
- `Filter` відповідає `Enumerable.Where`;
- `MaxBy` у цій роботі відповідає пошуку елемента з максимумом ключа; сучасний LINQ у .NET містить власний `MaxBy`;
- `ForEach` не є повним аналогом LINQ-оператора, але подібний до звичайного циклу та сторонньої ітерації з side effects.

Власні методи корисні для навчальних вимог, ізоляції інваріантів або бібліотек із мінімальною залежністю від LINQ. Для production-коду на сучасному .NET переважно краще використовувати перевірені LINQ-оператори.
