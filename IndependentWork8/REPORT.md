# Звіт до самостійної роботи No9

## Аналіз open-source прикладів

### 1. Dictionary: конфігурація та кеші у .NET Runtime

У .NET Runtime словники застосовуються для пошуку даних за стабільним іменованим ключем. Наприклад, у [StringDictionary](https://github.com/dotnet/runtime/search?q=StringDictionary&type=code) та [ObjectCache](https://github.com/dotnet/runtime/search?q=Dictionary%3Cstring&type=code) можливе O(1) середнє отримання і оновлення. `List<T>` у такому випадку вимагав би лінійного пошуку. При текстових ключах доречно використовувати `Ordinal` або `OrdinalIgnoreCase`; неправильне `GetHashCode()` може знизити продуктивність до O(n).

### 2. HashSet: унікальні члени в NuGet.Client

У [NuGet.Client](https://github.com/NuGet/NuGet.Client) множини використовуються для відстеження ідентифікаторів і уникнення дублікатів. Операції `Add`, `Contains`, `ExceptWith` та `IntersectWith` мають у середньому O(1)/O(n) зі складністю пропорційною кількості елементів множини. HashSet краще за List, коли важливі уникальність і перевірка належності.

### 3. Dictionary + HashSet: Dapper

У [Dapper](https://github.com/DapperLib/Dapper) словники використовуються для зберігання метаданих дескрипторів типів або прив’язаних параметрів, а множини — для обробки унікальних імен, індексів або набору значень. Така комбінація поєднує швидкий пошук за ключем із гарантією уникальності. Наприклад, слово як ключ і множина документів є фактичним інвертованим індексом.

## Порівняльна таблиця

| Операція | List<T> | Dictionary<TKey,TValue> | HashSet<T> | Коли використовувати |
|---|---:|---:|---:|---|
| Додавання | O(1) в кінець, O(n) у позицію | O(1) середньо | O(1) середньо | Список для порядку; Dictionary/HashSet для пошуку |
| Пошук за значенням | O(n) | O(n), якщо шукати значення; немає прямого індекса | O(n) за проекцією значення, немає пошуку за неключем | HashSet для належності |
| Пошук за ключем | Недоступно | O(1) середньо | Недоступно | Dictionary |
| Видалення | O(n) | O(1) середньо | O(1) середньо | Dictionary/HashSet |
| Перевірка наявності | O(n) | O(1) середньо за ключем | O(1) середньо | HashSet або ключ словника |

У наведених оцінках гіршого випадку операції Dictionary/HashSet можуть бути O(n) при колізійних key hash або зламаній реалізації comparer.

## Власний код

Реалізовано три сценарії:

1. `FileMetadataCache` зберігає метадані за іменем файла. Використано `StringComparer.OrdinalIgnoreCase`.
2. `TagManager` зберігає для кожної статті `HashSet<string>` і демонструє `UnionWith`, `IntersectWith`, `ExceptWith`.
3. `SearchIndex` будує `Dictionary<string, HashSet<int>>`: за словом знаходиться множина документів.

Приклад очікуваного виводу:

```text
=== Сценарій 1: Кеш метаданих ===
Спрацював пошук без урахування регістру REPORT.pdf/report.pdf
містить Photo.jpg: True
видалено REPORT.pdf: True

=== Сценарій 2: Унікальні теги ===
Усі теги: C#, LINQ, PLINQ
Спільні теги: LINQ

=== Сценарій 3: Пошуковий індекс ===
c#: 1, 2, 3
Dictionary+C#: 3
```

## Висновки

`Dictionary` краще за `List`, коли дані мають ідентифікатор і потрібні часті пошук, оновлення та видалення за ключем. `HashSet` оптимальний для уникнення дублікатів і операцій над множинами. Основні підводні камені: змінюваний ключ або об'єкт з некоректним `Equals/GetHashCode`, неузгоджений comparer, нестабільність у багатопотоковому використанні та коректна реалізація case-sensitive/case-insensitive поведінки.
